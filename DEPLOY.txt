================================================================================
GPS-FAMILIA — DEPLOYMENT CHECKLIST & STEP-BY-STEP GUIDE
================================================================================
Read this file top to bottom the first time. You do not need to be a developer.
Every command is copy-paste. Free options are marked FREE.

What this app is
----------------
A family location + encrypted chat web app. The Node.js server (server.js)
serves the website, the API, and a live WebSocket. Users open it in a browser
(or as an installed app / APK wrapper). Locations of other people are NEVER
shown unless they share a family with you.


================================================================================
A. QUICK LOCAL RUN (your computer)
================================================================================
You need: Node.js 18+ from https://nodejs.org  (LTS). Optional: Python 3.

Windows
  1. Double-click Start.bat
  2. Wait until a browser tab opens at http://127.0.0.1:3000/

macOS / Linux
  1. Open Terminal in this folder
  2. python3 start.py

Manual (any OS)
  npm install
  copy .env.example to .env     (Windows: copy .env.example .env)
  node server.js

CHECKLIST — local
  [ ] Node.js 18+ installed (`node -v`)
  [ ] `npm install` finished with no errors
  [ ] `.env` exists (start.py / Start.bat creates it)
  [ ] Browser opens http://127.0.0.1:3000/
  [ ] Animated splash, then the full Terms of Use (checkbox + I Agree)
  [ ] Log in / Register (or tap a sample family member; password demo123)
  [ ] You can register, create a family, turn Track On, send a message
  [ ] In-app messages are gold-framed popups — never the browser's ugly alert()
  [ ] Health check: http://127.0.0.1:3000/api/health  shows {"ok":true,"version":"2.4.0",...}
  [ ] Persist the uploads/ folder (feed photos and videos). Do not commit user media.
  [ ] /api/config includes vapidPublic (phone lock-screen alerts are armed)


================================================================================
B. CONFIGURATION (.env) — what each line means
================================================================================
PORT=3000                 Web port. Hosts like Render set this for you.
HOST=0.0.0.0              Listen on all interfaces (required on servers).

OTP_ECHO=true             LOCAL ONLY. Puts the 6-digit code in the API so
                          login works without SMS. Set to false in production
                          once email or Twilio is configured.

GOOGLE_CLIENT_ID=         Paste your Google OAuth Web Client ID here
                          (looks like 123456789-xxxx.apps.googleusercontent.com)
                          In-app Help is for family users only — paste the ID
                          in .env, not in the Help menu.

VAPID_PUBLIC / VAPID_PRIVATE / VAPID_MAILTO
                          Lock-screen Web Push keys. Leave blank: the server
                          creates them on first boot and saves them in
                          f360_data.json. On a new host, copy the keys into
                          .env so existing phone subscriptions keep working.

SMTP_HOST / SMTP_PORT / SMTP_USER / SMTP_PASS / FROM_EMAIL
                          Optional. Gmail: create an App Password
                          https://myaccount.google.com/apppasswords
                          SMTP_HOST=smtp.gmail.com   SMTP_PORT=587

TWILIO_SID / TWILIO_TOKEN / TWILIO_FROM
                          Optional SMS OTPs. Free trial at https://www.twilio.com

CHECKLIST — production .env
  [ ] OTP_ECHO=false
  [ ] GOOGLE_CLIENT_ID set if you want Sign in with Google
  [ ] SMTP or Twilio set if you want real OTPs (otherwise password + Google)
  [ ] Never commit .env or f360_data.json to a public git repo

C. EASIEST FREE WAY TO HOST THIS FOR YOUR USERS  (recommended: Render)
================================================================================
This app is a Node server with WebSockets. Static hosts (GitHub Pages,
Netlify, Cloudflare Pages) CANNOT run it by themselves. You need a free
Node host. Render.com is the simplest as of 2026.

----- Option 1 (EASIEST, FREE): Render Web Service -----
https://render.com   Free "Web Service" (spins down after idle; first
load may take ~30–60 seconds. Fine for families.)

1. Create a free GitHub account if you don't have one: https://github.com
2. Put this project in a GitHub repository:
     - Install GitHub Desktop (https://desktop.github.com) OR use:
         git init
         git add .
         git commit -m "GPS-FAMILIA"
     - On github.com click New repository → create → push
     IMPORTANT: do NOT upload .env or f360_data.json (they are in .gitignore)
3. Go to https://dashboard.render.com → New → Web Service
4. Connect the GitHub repo
5. Settings:
     Runtime: Node
     Build command:   npm install
     Start command:   node server.js
     Instance:        Free
6. Environment variables (Add):
     NODE_VERSION          20
     HOST                  0.0.0.0
     OTP_ECHO              false
     GOOGLE_CLIENT_ID      (your client id, see section D)
     SMTP_HOST / USER / PASS / FROM_EMAIL   (optional)
7. Create Web Service. Render gives you a URL like:
     https://gps-familia.onrender.com
8. Open that URL. Register. Send the URL to your family.

Notes
  • Free Render sleeps after ~15 min idle. First visitor waits for wake-up.
  • Data is stored in f360_data.json on the server disk. On the FREE plan
    that disk can reset if the instance is replaced. For a family of a few
    people this is usually OK. For something more durable, later add a
    paid disk or switch to a $5 VPS (see Option 3).
  • HTTPS is automatic on Render. Phones REQUIRE https for GPS and Google.

----- Option 2 (FREE): Fly.io -----
https://fly.io
  1. Install flyctl: https://fly.io/docs/hands-on/install-flyctl/
  2. fly auth signup
  3. In this folder: fly launch
  4. Accept the Node app defaults, do NOT add a Postgres database
  5. fly secrets set OTP_ECHO=false GOOGLE_CLIENT_ID=your-id
  6. fly deploy
  You get https://something.fly.dev

----- Option 3 (FREE forever VPS): Oracle Cloud Always Free -----
A real Linux server, never sleeps. Harder first hour, then rock solid.
  1. https://www.oracle.com/cloud/free/  → Always Free ARM VM
  2. Create an Ubuntu instance, open ports 80 and 443 in the VNIC firewall
  3. SSH in, install Node 20:
       curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
       sudo apt-get install -y nodejs nginx
  4. Upload this folder (scp / Git)
  5. npm install && node server.js   (use pm2 to keep it alive:
       sudo npm i -g pm2
       pm2 start server.js --name familia
       pm2 startup && pm2 save)
  6. Point a free domain (https://www.freenom.com is gone; use
     https://www.duckdns.org or Cloudflare) at the VM
  7. HTTPS with Caddy or Certbot (Let's Encrypt, free)

----- Option 4 (almost free): Railway / Koyeb -----
Same idea as Render. Watch the free-credit limits.

NOT suitable by themselves
  GitHub Pages, Netlify, Cloudflare Pages, itch.io — they only serve
  static files. This app needs Node + WebSocket.

D. GOOGLE SIGN-IN  (free — takes about 5 minutes)
================================================================================
Google login is REAL. It talks to Google's servers. You must create a
free OAuth Client ID. There is no password stored for Google users.

1. Open https://console.cloud.google.com/
2. Sign in with any Google account → Create a new project (name: GPS-FAMILIA)
3. APIs & Services → OAuth consent screen
     User type: External  →  Create
     App name: GPS-FAMILIA
     User support email: your Gmail
     Developer contact: your Gmail
     Save and continue through Scopes (default is fine)
     Test users: add the Gmail addresses of your family while the app is
     in "Testing". You can later click Publish app (still free).
4. APIs & Services → Credentials → Create credentials → OAuth client ID
     Application type: Web application
     Name: GPS-FAMILIA web
     Authorized JavaScript origins — ADD BOTH:
         http://localhost:3000
         http://127.0.0.1:3000
         https://YOUR-RENDER-URL.onrender.com     (no trailing slash)
     Authorized redirect URIs — same origins are enough for this app
     (GIS id_token flow does not need a redirect URI, but adding the
     origin URL does not hurt)
5. Copy the Client ID (….apps.googleusercontent.com)
6. Put it in .env as GOOGLE_CLIENT_ID=..... and restart the server
7. Log out → you should see "Continue with Google"

F. TURN THIS INTO AN ANDROID APK  (easiest FREE methods)
================================================================================
The app is already a PWA (Progressive Web App). That is the key.

----- Method 1 (EASIEST, FREE): PWABuilder -----
https://www.pwabuilder.com

1. Deploy the web app with HTTPS (section C). PWABuilder cannot wrap localhost.
2. Open https://www.pwabuilder.com
3. Paste your live URL  → Start
4. Wait for the score. Package for Android.
5. Options:
     Package ID:  com.yourname.gpsfamilia
     App name:    GPS-FAMILIA
     Host:        your domain
     Display:     standalone
6. Download the zip. Inside you get:
     - an .apk  you can sideload (enable "Install unknown apps")
     - an .aab  for Google Play
7. To install on a phone without Play:
     send the .apk to the phone → open it → Install

This uses Trusted Web Activity: it is your real website inside a tiny
Android wrapper. Updates to the website update the "app" automatically.

----- Method 2 (FREE): Bubblewrap / TWA command line -----
https://github.com/GoogleChromeLabs/bubblewrap
  npm i -g @bubblewrap/cli
  bubblewrap init --manifest https://YOUR-SITE/manifest.json
  bubblewrap build
Needs Android Studio / JDK. More control, same result as PWABuilder.

----- Method 3: Capacitor (if you later want native plugins) -----
https://capacitorjs.com   (open source, free)
  npm i -g @ionic/cli
  npm i @capacitor/core @capacitor/cli @capacitor/android
  npx cap init "GPS-FAMILIA" com.yourname.gpsfamilia --web-dir .
  npx cap add android
  npx cap copy && npx cap open android
Then build an APK in Android Studio (Build → Build Bundle(s) / APK(s)).
You would still point Capacitor at your hosted HTTPS server for the API
(set server.url in capacitor.config.json) because GPS + chat need the backend.

CHECKLIST — Android
  [ ] Site is on HTTPS
  [ ] /manifest.json loads
  [ ] /icon-192.png and /icon-512.png load
  [ ] PWABuilder packages without errors
  [ ] APK installs and Sign in with Google works (add the package's
      digital asset links if Play requires it; PWABuilder documents this)

G. iOS — easiest paths (Apple does not allow sideloading like Android)
================================================================================
Apple does not let you email an .ipa to family the way Android does with
an .apk, unless you pay $99/year for an Apple Developer account.

----- Method 1 (EASIEST, FREE): Add to Home Screen -----
This is how most family apps ship on iPhone without an App Store listing.

1. Deploy the site on HTTPS (section C)
2. On iPhone / iPad, open Safari (not Chrome)
3. Visit your URL
4. Tap the Share button (square with arrow)
5. Tap "Add to Home Screen"
6. Name it GPS-FAMILIA → Add

It opens full-screen like a native app. Push GPS, chat, Google login all
work (Safari). Tell your family these 4 steps once.

----- Method 2: Capacitor → Xcode → TestFlight / App Store -----
Needs: a Mac, Xcode (free on the Mac App Store), and an Apple Developer
Program membership ($99/year) to install on other people's phones.

  npm i @capacitor/ios
  npx cap add ios
  npx cap copy ios
  npx cap open ios

In Xcode: pick your Team, set a Bundle ID, Product → Archive, upload to
App Store Connect / TestFlight. TestFlight is the easy way to invite
family testers.

----- Method 3: PWABuilder iOS package -----
PWABuilder can also spit out an Xcode project. Same $99/year rule to
distribute. For a family of relatives, Method 1 is the rational choice.

================================================================================
I. TROUBLESHOOTING
================================================================================
Blank map
  Leaflet/OSM needs internet. Corporate Wi-Fi may block tile servers.

Google button missing / "origin not allowed"
  Add the EXACT URL (https://gps-familia.onrender.com) to Authorized
  JavaScript origins. Wait 1–2 minutes. Hard-refresh.

GPS says denied
  Browser padlock → Site settings → Location → Allow.
  iOS: Settings → Safari → Location. Android Chrome: Site settings.

OTP never arrives
  With OTP_ECHO=true the code is shown in a centered in-app popup and in
  the server log. In production set SMTP or Twilio, and OTP_ECHO=false.

Lock-screen notifications never appear
  Requires HTTPS (or localhost), a service worker, and Allow on the
  browser prompt. Check /api/config → vapidPublic is a long string.
  iPhone: Add to Home Screen first, then open from the icon and Allow.
  Android Chrome: Site settings → Notifications → Allow.

WebSocket / "live" never appears
  Proxies must allow Upgrade headers. Render and Fly do. nginx needs:
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";

Data vanished on Render free
  The free instance was replaced. Export is: download f360_data.json
  from the host (SSH / disk) and keep a backup. Or move to a VPS.

Port already in use locally
  Change PORT in .env, or close the other node process.
