2. LOCAL RUN (step by step)
---------------------------
  1. Node 18+ (`node -v`).
  2. npm install --omit=dev     (if node_modules was wiped, always reinstall)
  3. cp .env.example .env       (Start.bat / start.py do this)
  4. node server.js
  5. Open http://127.0.0.1:3000/
  6. Splash → Terms checkbox → I Agree → compact login card.
  7. Demo: vito@familia.test / demo123   or tap a sample member.
     OTP 000000 when DEMO_MODE is true.
  8. curl http://127.0.0.1:3000/api/health
      Expect: {"ok":true,"version":"2.17.0","realtime":true}

  If express MODULE_NOT_FOUND: npm install, then start again.
  Do not pkill in a way that deletes node_modules (sandbox snapshots
  exclude node_modules).


3. CONFIGURATION (.env) — implementation notes
----------------------------------------------
  PORT / HOST             Listen. Render/Fly set PORT. HOST=0.0.0.0 on servers.
  OTP_ECHO=true           Local: OTP is returned in the API + printed in logs.
  DEMO_MODE=true          Seeds Vito/Sonny/… and accepts OTP 000000 / 123456.
  GOOGLE_CLIENT_ID        GIS id_token. Origins must match exactly.
  SMTP_* / TWILIO_*       Real OTPs. Leave blank in demo.
  VAPID_*                 Auto-generated into f360_data.json if blank.
  LIVEKIT_URL             wss://…  When set, calls-server.js mints HMAC JWTs.
  LIVEKIT_API_KEY/SECRET  Same as LiveKit server. No livekit-server-sdk dep —
                          HMAC is implemented in calls-server.js on purpose.
  TURN_URL/USER/PASS      Added to GET /api/calls/ice alongside Google STUN.
  MATRIX_HOMESERVER       Optional. Default Matrix ids are
                          @u_<id>:gps-familia.local via GET /api/matrix/whoami.

  After changing .env, restart node. Client reads live values from GET /api/config
  (applyServerConfig → window.__serverConfig).


4. AUTH FLOW
------------
  POST /api/register      { name, email, phone, password }
  POST /api/login         { identifier, password }  → { user, sessionToken }
  POST /api/auth/google   { credential } GIS JWT
  POST /api/send-otp  /  POST /api/verify-otp

5. FAMILIES, LOCATION, MESSAGES
-------------------------------
  POST /api/families              create { name, password, privacy }
  POST /api/families/:id/invite   mint { token, url, qrUrl }  (token includes from)
  GET  /api/invite/preview        ?token=  auth required. Members, roles, rules,
                                  invitedBy, alreadyMember. Does NOT join.
  POST /api/families/join         { token } — kept for tests; Accept in the UI
                                  calls this after the preview.
  GET  /invite/:token             302 → /?invite=TOKEN  (opens the PWA)
  Deep link: unsigned users Register/Log in first. After auth, preview then
  Accept/Decline. Already-members see the briefing only.
  POST /api/families/:id/join     password / public / request
  GET  /api/sync                  users + families + rooms + messages + places
  POST /api/location              { lat, lng, type, record }
  GET  /api/locations             family pins only
  POST /api/messages              { to | familyId | roomId, enc }
  DELETE /api/messages/:id
  WS type=location | message | sos | family | typing | presence | room | call | feed

  Encryption: AES-GCM on the device (app.js deriveConvKey). SOS is plaintext
  by design so every family phone can read an emergency.


6. CALLING (do not rebuild inbox)
---------------------------------
  REST
    POST /api/calls          { toUserId | familyId | roomId, kind: "voice"|"video" }
    GET  /api/calls/:id
    POST /api/calls/:id/hangup
    GET  /api/calls/ice      STUN (+ TURN if env)

  UI: chatCallBtns on DM / family / room headers. Overlay .call-layer.
  Deep link: /?call=<id> from a notification.
  Client: importmap livekit-client@2.15.7 in index.html.

---------------------------------------------------

  market-server.js      /api/market*  realtime WS type=market
  pay-server.js         /api/pay/*    Stripe REST + Plaid REST (no extra npm)

  Block: POST /api/blocks { userId }  DELETE /api/blocks/:userId

    booleans: appearOnMap, preciseLocation, showLastSeen,
      shareEmailWithFamily, sharePhoneWithFamily, allowHistory, recordHistory,
      shareEmailWithFriends, sharePhoneWithFriends, shareLocationWithFriends,
      allowFriendRequests, appearInSearch, showOnlineStatus,
      allowMarketplaceContact, readReceipts, typingIndicators, hideBlockedInSearch
    enums: allowMessagesFrom anyone|friends|family|nobody
           allowCallsFrom anyone|friends|family
           showProfileTo everyone|friends|family

  Family join returns { family, briefing } with role, privileges, role list,
  youCan, theyCan. GET /api/families/:id/briefing for members.

  Marketplace: signed-in catalog. Listings store city + fuzzed lat/lng only.
  Buyer Message opens encrypted /api/messages with the seller.
  Offers: POST /api/market/:id/offer { amount } — seller accept/decline.

  Wallet: never accepts full PAN, CVC, or routing numbers (400).
  Stripe: STRIPE_SECRET_KEY + STRIPE_PUBLISHABLE_KEY → SetupIntent + PaymentIntent.
  Plaid: PLAID_CLIENT_ID + PLAID_SECRET → /link/token/create + exchange.
  Without keys, demo vault stores last4 + brand + expiry / bank last4.

  Tests: npm test  (suites social + market)


14. P2P MARKETPLACE FEE (v2.10.0)
---------------------------------
  Buyer pays listed price + 6.9% service fee.
  Floor $0.49, cap $25. Seller receives 100% of the item price.
  POST /api/pay/quote { amount } → { item, fee, total, sellerReceives }
  POST /api/pay/p2p { listingId, amount, methodId }  (saved card, never PAN)
  Rationale: OfferUp-class 6.9% covers Stripe ~2.9%+$0.30 plus ~3–4% platform
  margin. Buyer-pays keeps sellers whole (local classifieds trust). Cap protects
  furniture-priced tickets. Free listings: no fee.

  GET /api/market filters: q, category, condition (new|used|like_new|good|fair|for_parts),
  minPrice, maxPrice, miles, lat, lng, sort=newest|price_asc|price_desc|distance,
  status=active|sold|all, filter=mine|saved.
  Demo listings: lst_demo_* flagged demo:true with photos in /market-demo/.


15. PEOPLE GRAPH, QR, NOTIFICATIONS (v2.17.0)
---------------------------------------------
  Relationship state is computed on the server (modules/social/graph.js).
  Frontend only renders `relationship.label` and `relationship.actions`.
  GET  /api/users/:id/relationship
  GET  /api/search           q, limit, offset. Channel prefs:
                             findByName everyone|friends|nobody
                             findByEmail / findByPhone everyone|nobody
                             Phone matches strip a leading US +1.
  POST /api/friends/request  never auto-accepts
  POST /api/friends/:id/cancel   sender only
  POST /api/friends/:id/accept   idempotent if already accepted
  GET  /api/friends/requests

  Message requests (strangers; default allowMessagesFrom=anyone):
    POST /api/messages { to }  → { requested:true }  (not stored in DB.messages)
    GET  /api/messages?with=   empty until accept
    GET  /api/message-requests
    POST /api/message-requests/:id/accept|decline
    On accept, pending ciphertext is copied into DB.messages.

  QR (never auto-executes):
    POST /api/qr/generate { type: profile|friend|family|payment|app, amount?, familyId? }
    POST /api/qr/resolve  { token } → { kind, confirmRequired, user|family|amount }
    GET  /qr/:token  → /?qr=  then in-app confirm
    Family invite tokens still preview via findInviteFamily (Accept required).

  In-app notifications (complements Web Push, does not replace it):
    GET  /api/notifications  ?filter=all|unread|friend|family|message|payment
    GET  /api/notifications/summary
    POST /api/notifications/:id/read
    POST /api/notifications/read-all
    WS type=notification | message_request | friend

16. LIVE PINS, CHILD ACCOUNTS, SEARCH (v2.17.0)
-----------------------------------------------
  Developer / copyright: Deserius Arte © 2026.

  Family create: POST /api/families always mints an invite. Blank name becomes
  "<user>'s Family". Client uses apiCatch so errors are shown. Families stay
  in the directory until deleted. Public families are always searchable;
  private families are invite-only.

  Map: POST /api/location { tracking:false, type:"preview" } places YOU on your
  map without sharing. Other members only receive a pin while tracking is true.
  POST /api/me/tracking { on:false } hides you from others. Live pins pulse.

  Child register: { accountType: "child" }. Marketplace 403. DMs only family
  and friends. Friend requests and family invites still work.

  Families are location-safety groups only. Friend requests, Accept, and
  personal QR work with zero families. POST /api/people/invite without
  familyId creates a friend request. GET /api/people/hub includes
  incomingFriends / outgoingFriends. Preview iframe: Permissions-Policy
  camera=*, microphone=*, geolocation=* so calls/QR scan can prompt.
